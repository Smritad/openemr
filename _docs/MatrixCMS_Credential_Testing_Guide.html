1. Purpose & How to Use This Test Guide

This guide lets a tester log in with every MatrixCMS account, verify each login behaves correctly, and walk the Patient-details flow step by step. Each test case has an ID, exact steps, the expected result, and a blank Result column to mark PASS / FAIL.

Scope of this round. Appointment, Fees/Billing, and claim data are treated as cleared — only patient details are retained. So when you open Calendar / Fees / Visit History you should expect empty lists; that is correct for this round. The functional walk-through therefore uses the Patient module as the test path.

What "Authorized" means here (important for testing). In OpenEMR, Authorized = the user is a clinical provider who can be the rendering/authorizing provider and can eSign/authorize encounters. It is not the same as "can log in." So nurse.jane and reception.maya (Authorized = no) can still log in, but they cannot eSign clinical items. Test both facts.

Don't guess passwords. Repeated wrong attempts increase the Failed Login Counter and can lock an account. If you don't know a password, have the admin reset it via Admin > Users > (user) > set new password.

4. Login Flow, Validation & Post-Login Redirection

Authentication process (what happens on Login)

1User enters Username + Password and clicks Login
2Server looks up the username in users and the password hash in users_secure
3Password is verified (bcrypt hash compare). Technical note: handled by OpenEMR's auth/session layer.
4If valid → a session is created, the user's ACL group & permissions are loaded, and Failed Login Counter resets to 0
5Browser is redirected to interface/main/tabs/main.php (the main screen)
6The top menu is built based on the user's role/permissions — different roles see different menus
7The login event is written to the audit log table

Forgot / Reset password flow

MatrixCMS uses admin-driven password reset by default (no public "forgot password" email unless the patient portal/email is configured). To reset:
1Admin logs in as FTS-admin-63
2Admin > Users > User/Groups → click the target username
3Enter a new password (and confirm) → Save
4If the account was locked, saving also clears the Failed Login Counter
5User logs in with the new password (may be prompted to change it)
