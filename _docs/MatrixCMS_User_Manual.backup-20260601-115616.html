1. System Overview & Architecture

MatrixCMS is a multi-user Electronic Health Records (EHR) system used by clinics to manage:

Clinical Operations

  • Patient records and history
  • Encounter notes (SOAP)
  • Prescriptions
  • Lab orders & results
  • Vitals tracking

Business Operations

  • Appointment scheduling
  • Billing & claims
  • Insurance management
  • Patient communication
  • Recalls & reminders

How One App Serves Many Roles

┌──────────────────────────────┐ │ SAME DATABASE │ │ (patients, charges, notes) │ └──────────────┬───────────────┘ │ ┌──────────┬───────────────┼───────────────┬──────────┐ ▼ ▼ ▼ ▼ ▼ ┌────────┐ ┌────────┐ ┌─────────┐ ┌──────────┐ ┌──────────┐ │ ADMIN │ │ DOCTOR │ │ NURSE │ │RECEPTION │ │ PATIENT │ │ │ │ │ │ │ │ │ │ (portal) │ │ Full │ │Clinical│ │Clinical │ │Scheduling│ │ Limited │ │ access │ │+ Bill │ │ limited │ │ + Bill │ │ view │ └────────┘ └────────┘ └─────────┘ └──────────┘ └──────────┘
Key concept: Same data, different views. Each user logs into the same app but sees a customized menu based on their role.

The Permission Architecture

USER ACCOUNT │ ▼ ACL GROUP (Physicians / Front Office / etc.) │ ▼ PERMISSIONS LIST │ acct/bill/write │ patients/demo/write │ encounters/notes/write │ ... etc │ ▼ SHOWS/HIDES specific menus

🔢 4.4.2 Insurance Numbers — Provider Billing IDs

What is "Insurance Numbers"?

Each doctor has their own unique billing number with each insurance company. This screen stores those numbers.

The 3 Numbers Explained

NumberMeaningExample
Provider #Doctor's unique ID with this insurance companySH-DR-12345 (Dr. Smith with Star Health)
Rendering #The person who actually rendered the serviceUsually same as Provider # for solo doctors
Group #The clinic's overall ID with this insuranceCSAB-CLINIC-001 (all doctors share)

Step-by-Step

1Left sidebar → Click Insurance Numbers
2List shows all your providers (Dr. Smith, Dr. Kumar, etc.)
3Click on a doctor's name (e.g., John Smith)
4Form opens showing fields for EACH insurance company
5For each insurer, fill:
  • Provider # (from insurance company)
  • Rendering # (usually same)
  • Group # (your clinic's contract ID)
6Click [Save]
7Repeat for each doctor
If you don't have real numbers yet:
  • Leave as "Default" for testing
  • Or use placeholder: PENDING-001
  • Update when you receive real numbers from each insurer

🔍 4.4.4 HL7 Viewer — Debugging Tool

What is HL7 Viewer?

Tool for IT staff to view/parse HL7 (Health Level 7) messages — the international standard for healthcare data exchange.

What HL7 Looks Like (Raw)

MSH|^~\&|LAB|HOSP|EMR|CLINIC|20260528||ORU^R01|MSG001|P|2.3 PID|1||P1001^^^MR||Sharma^Amit||19850315|M ORC|RE|123|456||CM|||||20260528 OBR|1|123|456|CBC^Complete Blood Count^L OBX|1|NM|HGB^Hemoglobin||14.5|g/dL|13.5-17.5|N OBX|2|NM|WBC^White Cells||7500|/mm3|4500-11000|N

How to Use

1Receive HL7 file from external lab
2Left sidebar → Click HL7 Viewer
3Page shows text box "Paste HL7 Data"
4Open the HL7 file (.hl7 or .txt) in Notepad
5Copy all text
6Paste into the text box
7Click [Parse HL7] button
8System decodes into readable format:
  • Message Type: ORU^R01 (Observation Result)
  • Patient: Sharma, Amit
  • Test: CBC
  • Results: Hemoglobin 14.5 g/dL (Normal)
9Click [Clear HL7 Data] to start over
For most users: You'll RARELY use this. It's only for IT staff debugging lab integrations. Normal clinic staff can ignore this tab.

🔧 4.4.5 X12 Partners — EDI Clearinghouses

What is an X12 Partner?

Third-party service that forwards your electronic claims (X12 files) to multiple insurance companies.

How it works

YOUR CLINIC CLEARINGHOUSE INSURANCE ───────────── ───────────── ────────── Generate X12 → ──► X12 Partner ──► Star Health (middleman) Aetna forwards to Blue Cross each insurer etc.

Examples

RegionCommon Clearinghouses
USAAvaility, Trizetto, Change Healthcare, Office Ally
IndiaPracto Insurance, Babylon Health, MediAssist TPA

For Indian Clinics

If you don't have a clearinghouse yet → SKIP this section.
Most Indian clinics submit claims directly via:
  • Insurance company's online portal
  • Email (PDF claim form)
  • TPA (Third Party Administrator) physical submission
Configure X12 Partner only when you sign up with an EDI service.

DO ✅

23.3 What Care Coordination Actually Does

Care Coordination is the module that lets your clinic send a patient's medical summary to another doctor/clinic, and receive one back — using the standard electronic formats CCDA and QRDA. It is how MatrixCMS "talks" to other hospitals.

TermPlain meaning
CCDA"Continuity of Care Document" — a standard file holding meds, problems, allergies, visits. The universal patient-summary format.
QRDAA quality-reporting version of the same idea (for measures/reporting).
